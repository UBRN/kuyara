{%- comment -%} Everything the appearance button needs in : the stored choice applied to before the page paints, and the control's styling. Self-contained, so any layout can include it, and it belongs ahead of every stylesheet link so the attribute is set before the first style computation and no page paints in the wrong appearance. Every rule below is class-scoped, so the site's stylesheets that follow it settle any conflict by specificity, never by source order. The styling is written against the kuyara tokens in assets/css/tokens.css rather than theme utility classes, so it reads correctly in all three appearances and on a layout that does not load the theme CSS. Two attributes, one choice. `data-theme-choice` is always present once the script has run and carries `system`, `light` or `dark`; the control reads it to pick its icon. `data-theme` carries `light` or `dark` only when the choice overrides the operating system, which is the hook tokens.css and plates.css key their forced palettes off. The website animates always and does not consult the operating system's Reduce Motion setting, as recorded in product-decisions.md. There is no reduced-motion branch here. {%- endcomment -%}
