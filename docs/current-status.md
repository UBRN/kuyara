# Current Project Status

## Recently Completed Milestones

Keep only the most recent two or three completed milestones here. Older entries stay in Git history; this document describes the current state, not the full changelog.

Goal 2b, real AI provider adapters, was completed on 2026-08-19. `apps/worker/src/ai/openrouter-ai-provider.ts` and `workers-ai-provider.ts` implement the existing `AiProvider` seam; the contracts, `createAiHandler`, the router, and both endpoints are unchanged. A shared `ai-prompt.ts` holds one hand-written JSON Schema matching the success contract's shape exactly, so an adapter returns parsed model output with no mapping, plus a `buildMessages` builder that passes the already-sanitized request straight through. Both adapters send `max_tokens: 2048`, which is a correctness bound rather than a tuning knob: without it both runtimes returned truncated JSON that failed parsing or zod. The OpenRouter adapter keeps its API key in a private class field and throws only constant-message errors, so neither the key, the response body, nor provider identity can escape. `index.ts` moved composition into the request path — `fetch(request, env)` calls the exported `createAiProviders(env)`, which builds the Workers AI binding provider first and then one OpenRouter provider per configured model in order, making the handler's existing ordered walk the model fallback chain rather than adding a second loop. The chain was reordered on 2026-08-19 by user decision after the free-model evaluation showed Workers AI was the only provider returning valid output. Reordering exposed a second defect: the Workers AI hop measured 7.9 to 9.6 seconds against the handler's 10-second default, so roughly one run in five was aborted at the boundary and returned a spurious `ai_unavailable`. `index.ts` now passes `attemptTimeoutMs: 20_000` into the handler's existing injectable parameter, leaving the handler itself unchanged. After both changes five consecutive live runs returned HTTP 200 in 8.6 to 17.0 seconds, each contract-valid with three mutually distinct outfits. `DeterministicStubAiProvider` was removed from production composition, per the `AGENTS.md` rule that the deterministic sample provider is never a production fallback, and survives as an injected test double; `aiReady` is now real configuration state. Validation covered `pnpm check` (224 tests) plus live `wrangler dev` verification against the real providers: `/v1/ai/recommend` returned HTTP 200 with three contract-valid, mutually distinct outfits drawn only from the request's candidate set, and an all-providers-failed run returned exactly `503 ai_unavailable` with no provider detail. Nothing was deployed and no secret was set on the remote Worker. The seven free OpenRouter models that advertise structured outputs were each evaluated and none returned contract-valid output; Cloudflare Workers AI is currently the only provider that produces a valid recommendation. The evaluation table and the resulting open question are recorded in [`product-decisions.md`](product-decisions.md#free-model-evaluation-2026-08-19).

Goal 2a, provider-neutral AI recommendation contracts and Worker orchestration, was completed on 2026-08-14. `packages/contracts/src/ai-v1.ts` defines the strict `POST /v1/ai/recommend` request — clothing preference, the `ClothingRequirement` discriminated union, and a bounded array of sanitized candidates carrying only an opaque key, source kind, catalog type, color family, and structural property evidence — plus a success response of exactly three outfits built from ordered `{ slot, layerRole, candidateKey }` entries. Strictness is the privacy boundary: photos, paths, free-form names, profile or device identifiers, coordinates, and persistence lifecycle fields have no representation and are rejected. The candidate upper bound is 125, derived from a measured worst-case serialization of 494 bytes per candidate against a provider-neutral 64 KiB payload budget, and locked by a test; it is not a token count and assumes no model. Structural outfit invariants — exactly three outfits, one exclusive body core, exactly one footwear, at most one mid and outer layer, no repeated slot or candidate key — live in the shared schema, so the Worker adds only the closed-candidate-set membership check and no mobile scoring, requirement-satisfaction, diversity, or composition logic was duplicated. `createAiHandler({ providers })` walks an ordered provider list with a per-attempt `AbortController` timeout defaulting to 10 seconds, treats a throw, timeout, schema failure, or unknown candidate key as an eligible fallback, and collapses exhaustion into one sanitized `ai_unavailable`; the AI path emits no logs. Goal 2a ships one deterministic in-Worker stub provider, and test scenarios are chosen by injecting provider instances, never by a request field. A router adds `GET /v1/health` and the configuration-only `GET /v1/ai/ready`, which receives readiness as plain data and cannot call a provider, while `/v1/weather` keeps its existing behavior and error shapes. Both workspace `test` scripts moved from hand-listed files to `src/**/*.test.mjs` glob discovery so the new suites cannot be silently omitted. Validation covered `pnpm check`. No real AI provider, credential, binding, spend or rate limit, active probe, mobile client, or recommendation persistence was added.

An external-audit remediation pass was completed on 2026-08-13. It closed nine confirmed findings and one documentation conflict without changing architecture, adding a dependency, or altering visual design. The weather Worker provider is no longer constructed during module evaluation, so a missing production Worker URL now produces the existing localized unavailable state inside Weather instead of preventing the whole application from starting. Worker requests are bounded by a 10-second `AbortController` timeout covering both the response and its body, classified as the existing network failure. The weather persistence mapper now projects domain measurements explicitly, so `WeatherSnapshot.current` no longer carries `localProfileId` and other persistence metadata at runtime. The Today weather card exposes three semantic accessibility groups instead of one card-wide node, so wind, humidity, UV, sunrise, sunset, and the rain outlook are reachable by screen reader; the decorative glyph is hidden. The Today settings control and the Weather location control keep their intended visual size but reach the 44-point touch target through `hitSlop`. Weather metric values use localized formatters, so Turkish renders `m/sn` and a leading percent sign. Profile preference mutations serialize instead of coalescing, so a second distinct intent is no longer silently dropped. `ACCESS_FINE_LOCATION` was removed from the Android `permissions` array, leaving it blocked. Deleting a Wardrobe item now clears the stored photo path and removes the managed private file after the confirmed database write, aligning the implementation with `AGENTS.md`; `docs/architecture.md` was corrected accordingly and no restore flow was built. `docs/design/design-system.md` no longer carries a stale milestone inventory. Validation covered `pnpm check` and the separate component suite. The resolved Android manifest was not verified because `expo-location`'s config plugin re-adds the permission and only prebuild applies `blockedPermissions`; Simulator and physical-device accessibility verification were not performed in this pass.

## Development Environment

- Kuyara is an Expo SDK 57, React Native, and TypeScript pnpm workspace with `apps/mobile`, `apps/worker`, and `packages/contracts`.
- iOS is the first release target. Shared code and Expo configuration must keep Android buildable, while Android-specific feature work remains deferred.
- Codex is updated and healthy. Expo MCP is configured.
- XcodeBuildMCP is installed through Homebrew, configured for Codex, and has been verified through a successful iPhone Simulator build and launch.
- The generated local iOS project is not tracked. Its machine-local `apps/mobile/ios/.xcode.env.local` selects `/opt/homebrew/opt/node@24/bin/node`; the file is covered by the ignored generated `ios/` directory.
- Built-in Codex Memories are enabled. No separate Memory MCP is required.
- `AGENTS.md` contains the repository's efficient-execution rules and risk-proportionate validation strategy. `CLAUDE.md` only imports it, so the rules keep a single source.
- `.agents/skills/kuyara-next-goal/SKILL.md` is the single source for the repository-scoped workflow that selects, executes, and reviews Goals. `.claude/skills/kuyara-next-goal` is a relative symlink to that directory so Claude Code discovers the same skill; do not copy the file.
- Every workspace `test` script discovers suites through the `src/**/*.test.mjs` glob rather than a hand-listed file set, so a new suite cannot be silently omitted. The root `pnpm test` script runs them and is part of `pnpm check`.
- The development-only Worker is named `kuyara-weather-dev` and uses its assigned `workers.dev` URL. The deployment has no bindings, secrets, credentials, persistence, analytics, custom domain, or production WeatherKit access.

Deterministic three-outfit generation, the minimum safety prerequisite for AI, is complete, and Goal 2a's contracts and Worker orchestration are now in place behind a deterministic stub provider.
