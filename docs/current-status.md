## Recently Completed Milestones

Keep only the most recent two or three completed milestones here. Older entries stay in Git history; this document describes the current state, not the full changelog.

Milestone 4, the generation-mode status surface plus the active AI probe and Worker-side rate limiting, was completed on 2026-08-29. Design and the recalculated provider pricing behind the probe limits are canonical in [`adr/0001-worker-ai-probe-and-rate-limiting.md`](adr/0001-worker-ai-probe-and-rate-limiting.md), the repository's first ADR. Contracts gained `aiProbeV1Path`, `aiProbeV1SuccessSchema` (`{ status: 'ok' | 'unavailable', checkedAt }`), and a `rate_limited` error code. `apps/worker/src/ai/probe-handler.ts` is a new injected handler behind `POST /v1/ai/probe`: it method-gates, applies a per-IP burst limit, serves a 60-second isolate cache, enforces a KV daily counter capped at 30, then runs only the first provider once against a fixed minimal in-Worker request with a 20-second timeout, returning `ok` only when the output passes the same structural and closed-candidate-set validation a real recommendation uses. `createAiHandler` gained an optional per-IP rate limiter for `POST /v1/ai/recommend`; both use the native Cloudflare rate-limit binding, and `wrangler.jsonc` adds `PROBE_COUNTER` KV and the two `ratelimits`. Missing bindings degrade to permissive, so local dev and tests are unchanged. On mobile, Today shows a text-labelled `Pill` ("AI-assisted" / "Standard recommendation") next to the recommendation heading, driven by the existing snapshot `generationMode` with no domain change; Settings gained an "AI status" section with a last-recommendation line, a "Check AI status" action backed by a new sanitized `WorkerAiProbeClient` and `useAiProbe` hook, and an inline Reanimated pulsing-dots loading overlay that respects Reduced Motion. All copy is localized in Turkish and English; provider names, model identity, and technical failures never reach the client. Validation covered `pnpm check`, `pnpm --filter @kuyara/mobile test:components` (80 tests), and a Simulator check confirming the Today generation-mode `Pill` and the full Settings "AI status" section render correctly in the running app; the probe interaction itself (loading overlay, result copy, Reduced Motion) is covered by component tests because the Simulator UI-automation tools were unavailable. Nothing was deployed; the Codex review-gate lane hit an external usage limit before finishing and its pass was completed in the main agent instead.

The mobile UI redesign was completed on 2026-08-29, finishing the work landed deliberately unfinished as `fdc4371` on 2026-08-04. The redesign's own surface (the `Pill` and `PhotoPlaceholder` primitives, the `eyebrow` typography role, the `withAlpha` helper, the Today weather card and glyph, the outfit detail screen, and the shared visual language applied across onboarding, Settings, Wardrobe, Weather, and the tab bar) is unchanged in intent; what this milestone added is the conformance, accessibility, localization, and device verification the original commit explicitly did not claim. Six defects were found and fixed. The weather card authored its own `fontSize` and `lineHeight`, which defeated the natural-line-height release `AppText` performs above a 1.5 font scale and clipped the condition line and stat values at accessibility text sizes; both now use the `label` role. The muted rain bar measured 1.55:1 in light and 2.03:1 in dark against the card, below the 3:1 threshold for meaningful non-text content, and its tint moved from `brandAccent` at 0.3 to 0.7 (3.15:1 and 4.97:1). `PhotoPlaceholder` clipped its label inside the 56-point Wardrobe thumbnail and now renders the label only at 96 points and above. The outfit detail route passed a literal arrow into a `Button` label, so a screen reader announced the glyph as part of the accessible name; it now uses the localized `today.backAction` key. Today's rain probability was built by concatenating a bare `%` onto a formatted number, which put the sign on the wrong side in Turkish, and now uses `Intl.NumberFormat` percent style. The `eyebrow` role's `textTransform` uppercased with the device locale rather than the app language, rendering "BUGÜN IÇIN ÖNERILEN" instead of "BUGÜN İÇİN ÖNERİLEN"; `AppText` now uppercases string content with the active language read from `LocalizationContext`. Two further defects were found during Simulator verification: the primary tab bar grew unbounded at accessibility text sizes, wrapping its labels to three lines and taking about 195 points of a 874-point screen, and its labels are now clamped to one line with tail truncation (73 points at the largest size, with the full name preserved in each tab's accessible name); and the Wardrobe item form's own `paddingTop` overrode the safe-area padding `Screen` applies, pushing its heading under the status bar and Dynamic Island on both the create and edit routes. Token leaks were closed with a new `interaction.disabledOpacity` token. Verification covered `pnpm check`, `pnpm --filter @kuyara/mobile test:components`, and an iPhone 17 iOS 26.3 Simulator sweep of Today, Weather, Settings, Wardrobe list and form, onboarding, and the outfit detail screen in Turkish and English, light and dark, at text sizes from default through the largest accessibility size. New regression coverage asserts WCAG contrast for the redesign's tinted surfaces, forbids literal `fontSize`/`lineHeight` in `features/`, pins the one-line tab label contract, pins the Turkish eyebrow casing, and pins the form's safe-area padding. [`design/design-system.md`](design/design-system.md) now documents `Pill`, `PhotoPlaceholder`, the `eyebrow` role, `withAlpha`, the interaction opacity tokens, the contrast evidence for the new pairs, and the rule that feature code selects a typography role rather than authoring one.

Milestone 3, the mobile Worker AI client and device-local recommendation snapshot, was completed on 2026-08-24. `apps/mobile/src/features/recommendation/data/` gained `worker-ai-client.ts` (contract-validated HTTP call to `POST /v1/ai/recommend` with sanitized `WorkerAiClientError` failure kinds — no provider name, model identity, or raw response ever escapes), `worker-ai-recommendation-mapper.ts` (contract-to-domain mapping that re-validates every AI-returned candidate key and outfit shape against the domain composer rather than trusting or repairing it), `recommendation-repository.ts`, and `sqlite-recommendation-local-data-source.ts`, mirroring the existing weather-slice layering. `apps/mobile/src/features/recommendation/application/recommendation-application-controller.ts` coalesces duplicate concurrent refreshes into one in-flight request keyed by weather/location/context, falls back to the existing `composeOutfits` deterministic generator on any AI failure (tagged `deterministic-fallback` on the persisted snapshot vs. `ai-assisted`), and always preserves the last valid snapshot when a refresh fails. Refresh fires only on the approved triggers — a stale weather snapshot refreshed, active location change, clothing preference change, wardrobe content change, or an explicit request — never on a bare app launch. `apps/mobile/src/infrastructure/sqlite/migrations.ts` gained `migrationV5` (`latestDatabaseVersion` 4 → 5), a `recommendation_snapshots` table keyed uniquely per `local_profile_id`. The Today route, the outfit detail route, and `_layout.tsx` were rewired onto the new `RecommendationApplicationProvider` instead of computing `recommendOutfits` inline. This work was originally produced by a Codex write lane that then entered a non-converging review loop and was killed before its own review finished (see prior session notes in Git history); an independent line-by-line review against the Goal brief's acceptance criteria found and removed one leftover defect — a test for an unimplemented, out-of-brief cold-start cache-comparison trigger path that the interrupted loop never built — and found no other gap. Validation covered `pnpm check` and `pnpm --filter @kuyara/mobile test:components`.

Goal 2b, real AI provider adapters, was completed on 2026-08-19. `apps/worker/src/ai/openrouter-ai-provider.ts` and `workers-ai-provider.ts` implement the existing `AiProvider` seam; the contracts, `createAiHandler`, the router, and both endpoints are unchanged. A shared `ai-prompt.ts` holds one hand-written JSON Schema matching the success contract's shape exactly, so an adapter returns parsed model output with no mapping, plus a `buildMessages` builder that passes the already-sanitized request straight through. Both adapters send `max_tokens: 2048`, which is a correctness bound rather than a tuning knob: without it both runtimes returned truncated JSON that failed parsing or zod. The OpenRouter adapter keeps its API key in a private class field and throws only constant-message errors, so neither the key, the response body, nor provider identity can escape. `index.ts` moved composition into the request path: `fetch(request, env)` calls the exported `createAiProviders(env)`, which builds the Workers AI binding provider first and then one OpenRouter provider per configured model in order, making the handler's existing ordered walk the model fallback chain rather than adding a second loop. The chain was reordered on 2026-08-19 by user decision after the free-model evaluation showed Workers AI was the only provider returning valid output. Reordering exposed a second defect: the Workers AI hop measured 7.9 to 9.6 seconds against the handler's 10-second default, so roughly one run in five was aborted at the boundary and returned a spurious `ai_unavailable`. `index.ts` now passes `attemptTimeoutMs: 20_000` into the handler's existing injectable parameter, leaving the handler itself unchanged. After both changes five consecutive live runs returned HTTP 200 in 8.6 to 17.0 seconds, each contract-valid with three mutually distinct outfits. `DeterministicStubAiProvider` was removed from production composition, per the `AGENTS.md` rule that the deterministic sample provider is never a production fallback, and survives as an injected test double; `aiReady` is now real configuration state. Validation covered `pnpm check`; the full Node suite now totals 265 passing tests. Live `wrangler dev` verification against the real providers returned HTTP 200 from `/v1/ai/recommend` with three contract-valid, mutually distinct outfits drawn only from the request's candidate set, and an all-providers-failed run returned exactly `503 ai_unavailable` with no provider detail. Nothing was deployed and no secret was set on the remote Worker. The seven free OpenRouter models that advertise structured outputs were each evaluated and none returned contract-valid output; Cloudflare Workers AI is currently the only provider that produces a valid recommendation. The evaluation table and the resulting open question are recorded in [`product-decisions.md`](product-decisions.md#free-model-evaluation-2026-08-19).

## Implemented Capabilities

- A device-local profile, accountless onboarding, and persisted language, theme, and clothing preference.
- Primary Today, Weather, Wardrobe, and Settings tabs.
- Local-first Wardrobe persistence and CRUD, including soft deletion and catalog-backed garment properties.
- A private, single-photo Wardrobe lifecycle covering system-library selection, resize/compression, relative-path persistence, replacement, removal, and safe cleanup, including private-file deletion when the owning item is deleted.
- Foreground-only manual or device location selection with localized permission handling.
- Device-local weather snapshots with exact 30-minute freshness behavior, stale-data preservation, manual refresh, and deterministic sample data fetched from the local Worker.
- A versioned Worker weather endpoint with shared runtime contracts, deterministic local mock data, and privacy-safe error handling.
- A controlled `workers.dev` deployment of the deterministic sample endpoint for explicit remote development use.
- A mobile HTTP weather provider with environment-aware Worker origins, runtime response validation, and explicit contract-to-domain mapping.
- Provider-neutral shared AI recommendation contracts, a Worker `POST /v1/ai/recommend` route with ordered provider fallback, per-attempt timeouts, structural and closed-candidate-set validation, sanitized failures, and non-AI liveness and configuration-readiness endpoints, now backed by real OpenRouter and Cloudflare Workers AI adapters composed from Worker configuration, with the deterministic stub retained only as a test double.
- Provider-independent mobile weather failure classification with localized offline/unavailable states, retry, and last-known-good preservation.
- Deterministic provider-independent conversion from validated weather snapshots into structured clothing-property requirements, with tested boundary, conflict, precedence, and remaining-hour behavior.
- Pure catalog/Wardrobe effective-property projection and deterministic per-garment eligibility, requirement evaluation, bounded scoring, over-protection penalties, and stable tie behavior.
- Pure one-outfit composition with separates/one-piece branches, runtime roles, collective mandatory validation, targeted protection authority, explicit protection-versus-breathability trade-offs, bounded scoring, deterministic ordering, and structured failures.
- Turkish and English presentation plus System, Light, and Dark appearance preferences.
- A mobile Worker AI client with contract validation and sanitized failure mapping, a device-local recommendation snapshot persisted per profile, refresh/invalidation limited to the approved change triggers with duplicate-request coalescing, and the deterministic generator wired in as the on-device fallback whenever AI fails.
- A coarse generation-mode indicator in Today (a text-labelled `Pill`) and Settings, a `POST /v1/ai/probe` endpoint that runs one bounded provider attempt behind a per-IP burst limit, a 60-second isolate cache, and a KV daily cap, a sanitized mobile probe client with a Settings "Check AI status" action and Reduced-Motion-aware loading animation, and per-IP rate limiting on `POST /v1/ai/recommend`.

Weather uses the local Worker's deterministic sample endpoint by default in development. Developers may explicitly select the remote development sample URL; production mobile configuration does not use it. Three-outfit diversity and the deterministic Today integration are now implemented: Today consumes the persisted recommendation snapshot, produced by AI when available and by the pure `recommendOutfits`/`composeOutfits` fallback otherwise, and renders real composed outfits instead of a fixture. Production WeatherKit is still not implemented. The approved AI-first strategy is now implemented end to end: the shared AI contract, the Worker AI route with ordered real-provider orchestration, the mobile Worker AI client, the device-local recommendation snapshot, the coarse generation-mode surface in Today and Settings, and the explicitly triggered rate-limited `POST /v1/ai/probe` with its Settings "Check AI status" action all exist. Both AI endpoints are rate-limited. The repository still contains no real weather provider. The recommendation survives a cold start via the persisted snapshot; it is recomputed only on the approved refresh triggers, not on every launch.
